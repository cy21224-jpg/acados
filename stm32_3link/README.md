# STM32F767ZI向け 3リンクパラメータ・EKF

`param_3link.c/.h`、`function_3link.c/.h`と、添付の`RIM_functions.c/.h`を組にして使います。
EKFは指定どおり**4状態・4入力・2観測**です。RIMの2ファイルは添付とバイト単位で同一です。
既存のmain、MPC、クロック、TIM周期、割込み、`.ioc`、リンカ設定はこの変更では編集していません。

## 配置

| コピー先 | ファイル |
|---|---|
| `Core/Inc` | `param_3link.h`, `function_3link.h`, `RIM_functions.h` |
| `Core/Src` | `param_3link.c`, `function_3link.c`, `RIM_functions.c` |

C99以上のCとしてビルドしてください。STM32CubeIDEの既存の`-std=gnu11`で使えます。
F767ZIのCortex-M7、`-mfpu=fpv5-d16 -mfloat-abi=hard`でクロスコンパイル・リンクを確認しています。
数値ライブラリには標準の`libm`も使います。既存プロジェクトのリンクコマンドにある`-lm`を維持してください。
すでにRIMを配置している場合、同じ関数を定義するCファイルを二重にビルドしないでください。

`param_3link.h`には宣言だけ、`param_3link.c`には実体を置いています。
mainに移動元の`sampling_time`、`Gr`、`th_res`などの実体定義が残っていると多重定義になります。
これらをモジュールへ移すときは、mainから同名の実体定義を除き、`#include "param_3link.h"`で参照します。
今回のZIPはmainそのものの書換えを行うプログラムではありません。

## 保持した値と修正した型

- モータ制御・装置パラメータなど82変数の型・要素数・初期値を保持しています。
  元のCファイルと初期値がバイト単位で一致することをテストしています。
- EKF用の9変数だけ、元の関数とRIMの`double`に統一しています。
  `y_k[2]`, `u_k_1[4]`, `x_hat_k_1[4]`, `P_k_1[4][4]`, `Rkf[2][2]`,
  `Qkf[4][4]`, `x_hat_k[4]`, `P_k[4][4]`, `M_wy_k_1`です。
  元の未指定の初期値はすべて0のままで、質量や共分散の設計値は補っていません。
- 不一致だったインクルードガードと、Cファイルにない別用途のR2R/DQN/CSV宣言を整理しました。
- 静的初期化を標準Cの定数式に変更しています。依存関係を持つKfp/Gr/Jmn/質量の元値は、
  `param_3link.c`先頭の`PARAM3_*_VALUE`で管理します。ゲインなどの数値は変更していません。

## EKFの式と修正

状態は`[速度v, 位置y, 環境粘性c, 環境剛性k]`、観測は`[速度, 位置]`です。
`dt = sampling_time`で、初期値は元の`1.0e-3f`を維持します。

```text
v_next = v - dt*(c*v + k*y)/M + dt*u[0]/M
y_next = y + dt*v            + dt*u[1]
c_next = c                  + dt*u[2]
k_next = k                  + dt*u[3]
```

`u[0..3]`の4成分をすべて保持しています。`u[0]`だけを使う場合、残る3成分を呼出し側で0にします。
それぞれ、速度方程式への力入力、位置への追加速度、粘性の変化率、剛性の変化率に対応します。
MPCの出力を接続する場合は、この予測式と実際に適用した入力の単位・意味を合わせてください。
`u[0]`へ加速度指令をそのまま渡せるかは、有効質量を含むモデル定義次第です。

元コードの修正点は、未定義状態変数の局所化、B行列のカンマ不足、未定義`T`の統一、
速度予測の末尾`+位置`を`+速度`へ直したことです。最後の修正は**数式の誤りの修正**です。
予測共分散は元どおり`F*P*F^T + B*Q*B^T`です。
`Qkf`をすでに離散化済みの雑音共分散として直接加える形式には変更していません。
事後共分散は丸め誤差に配慮してJoseph形式を使います。厳密演算では元の更新式と同じです。

行列積・転置・ベクトル積・加減算・単位行列・逆行列には添付のRIM関数を使用します。
`inv_mat(2, ...)`には正規化した観測共分散を渡し、戻り値を確認します。
質量0、NaN/Inf、不適切な共分散、特異な観測共分散ではエラーを返し、出力を更新しません。

## 呼び方

起動時に、装置に対応する正の`M_wy_k_1`、初期推定`x_hat_k_1`、初期共分散`P_k_1`、
観測雑音共分散`Rkf`、プロセス雑音共分散`Qkf`を設定してください。
共分散は対称・半正定値で、観測更新時の共分散が可逆となるように設計します。
未設定のままでは`M_wy_k_1 == 0`なので、EKFは`EKF_STATUS_INVALID_MASS`を返します。
`param_init()`は元の互換用として残し、値の自動設定や制御状態のリセットは行いません。

以下は観測更新の例です。追加の3入力を使わない例ですが、APIは4入力を受け付けます。

```c
#include "param_3link.h"
#include "function_3link.h"
#include "RIM_functions.h"

/* 質量・初期推定・P/R/Qは呼出し前に設計値を設定しておく。 */
EKF_Status UpdateEstimate(double velocity, double position, double previous_force)
{
    y_k[0] = velocity;
    y_k[1] = position;
    u_k_1[0] = previous_force; /* 直前区間に実際に適用した入力 */
    u_k_1[1] = 0.0;
    u_k_1[2] = 0.0;
    u_k_1[3] = 0.0;

    EKF_Status status = EKF(y_k, u_k_1, M_wy_k_1,
                            x_hat_k_1, P_k_1, Rkf, Qkf,
                            x_hat_k, P_k);
    if (status == EKF_STATUS_OK) {
        /* 次回の推定に今回の結果を引き継ぐ。 */
        copy_vec(4, x_hat_k, x_hat_k_1);
        copy_mat(4, 4, P_k, P_k_1);
    }
    return status;
}
```

元の`EKF`の引数順序を維持し、戻り値を`void`から`EKF_Status`にしています。
成功は0、引数不正-1、質量不正-2、共分散不正-3、観測共分散の特異性-4、数値異常-5です。
失敗時の出力には前回値が残るため、戻り値0のときだけ今回の結果として扱ってください。
状態と共分散を同じ入出力配列でインプレース更新する呼び方にも対応しています。
呼出し中は入力・出力の配列を別の割込みやタスクから更新しないでください。

## 検証と実機で確認する項目

- C11、`-Wall -Wextra -Werror -pedantic`、`-O0`と`-O3`で警告なしのコンパイル。
- Cortex-M7/FPv5-D16/hard-floatで、3つのCファイルと試験用ハーネスのリンク。
- 70桁Decimalによる独立した数式実装との比較、4入力すべての作用、連続推定、
  インプレース更新、異常入力時に出力を書き換えないことを確認。
- ARM命令エミュレーションで40回ずつ、`-O0`/`-O3`の結果を独立参照値と照合。
- RIMの2ファイルが添付と同一であることを確認。

ホスト上の数値テストは標準Pythonとgccだけで実行できます。

```bash
python3 stm32_3link/tests/test_ekf.py
```

実機の周辺機器・制御性能・1 ms以内の実行は未検証です。
試験ハーネスのARMエミュレーションではスタックを約2.2 KiB観測しました。
これは割込みの重なりや他の制御処理を含めた実機最大値ではありません。
既存の最小スタック予約1 KiBは変更していません。予約量はスタックの実際の上限ではありませんが、
実機ではヒープとの余裕・割込み込みの最大使用量を確認してください。
